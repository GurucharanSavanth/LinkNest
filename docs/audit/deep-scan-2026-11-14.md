# LinkNest repository audit — 2026-11-14

What this repo does: LinkNest stores a personal website library locally, with capture, categories, tags, search, health checks, backups, widgets, and shortcuts. This review assumes one user, hundreds to several thousand links, intermittent connectivity, and occasional backup imports.

Baseline: `0f9ad3a1017a6a261a44af61f4fe54465938a566`. Working tree was clean before review. No application code was changed. This is a repository-wide, risk-focused static audit, not proof that every line or device scenario is correct. Findings marked **static** follow directly from inspected code; runtime severity remains to be measured. Hypotheses are explicitly separated.

## Must fix

### 1. Image rendering bypasses outbound URL protections — high, static

- **What this is:** `core/model/.../Models.kt:82–89,146–149` passes website metadata URLs to `AsyncImage` in `DashboardScreen.kt:821` and `AddEditScreen.kt:780`. `LinkNestApplication.newImageLoader` configures caches but no public-target restriction.
- **Problem:** A public page can advertise a private HTTPS image URL, or an image URL that redirects there. `IconStorageManager` may reject it, but the UI still gives the remote URL to Coil. OG-image selection even skips an available cached icon. Actual reachability depends on TLS, routing, and the image client; no exploit was executed.
- **Fix:** Make every remote image fetch use the same enforced network policy, including redirects and resolved connection addresses; alternatively render only validated cached images and a local fallback. Do not weaken TLS or permit arbitrary imported file/content URIs.
- **If skipped:** Rendering saved or imported content can trigger unintended network requests; offline images and download limits also become inconsistent.

### 2. Duplicate “merge” and “move” overwrite personal fields — high, static

- **What this is:** `core/action/.../pipeline/AddWebsitePipeline.kt` maps REPLACE_EXISTING, MERGE_METADATA, and MOVE_EXISTING to one existing ID and one `PersistWebsiteRequest`.
- **Problem:** All three choices write incoming note, tags, priority, follow-up, labels, pin and icon fields. A new capture with defaults can erase an existing note and tags even when the user selected “move” or “merge.” `OfflineFirstWebsiteRepository.addWebsite` applies these replacements.
- **Fix:** Move changes only category/order; merge preserves user fields and combines only explicitly defined metadata/tags; replace retains its explicit replacement semantics. Use the existing entry to construct each request.
- **If skipped:** User-authored information is silently lost. Add separate regression tests for every duplicate decision.

### 3. Selecting an import immediately replaces the library — high, static

- **What this is:** `SettingsScreen.kt:103,142,173–175,422` calls import directly; `OfflineFirstBackupRepository.clearForRestore` clears all library tables inside a transaction.
- **Problem:** A valid but unintended file replaces current records without a preview or explicit replacement confirmation. Database rollback protects failed transactions, not successful imports of the wrong file.
- **Fix:** Parse and validate first, show incoming/current counts and replacement semantics, then require explicit restore confirmation. Preserve a recoverable pre-restore snapshot and document rollback scope before extending restore behavior.
- **If skipped:** One mistaken file selection can replace the user's current library. Test cancel, failure, successful restore, and rollback.

### 4. Import input is unbounded before serializer limits — high, static

- **What this is:** `BackupFileManager.readFromUri` calls `bufferedReader().readText()`; `readStagedBackup` reads the entire file.
- **Problem:** `BackupSerializer.deserialize` checks size only after the entire string is allocated. A large document can exhaust memory before the existing compressed-payload guard runs.
- **Fix:** Bound streaming reads at the external input boundary, including providers without a reliable size. Apply consistent serialized and decompressed limits; keep the existing bounded gzip code.
- **If skipped:** Large or hostile imports can crash the app. Test exactly-at-limit, over-limit, unknown length, truncated input, and gzip expansion.

### 5. Category deletion leaves searchable deleted websites — high, static

- **What this is:** `OfflineFirstCategoryRepository.deleteCategory` deletes the category and cascading websites, then calls `removeCategory`.
- **Problem:** `AppSearchBackedSearchIndexRepository.removeCategory` reindexes websites by querying the already-deleted category. It gets no rows and never removes their old website documents. Search can still return deleted records and URLs.
- **Fix:** Capture website IDs before the transaction, remove those documents after commit, and reconcile interrupted index updates. Validate returned indexed IDs against authoritative Room data where needed.
- **If skipped:** Deleted links reappear in search, and the index diverges permanently until rebuilt.

### 6. URL normalization changes encoded URL meaning — high, static

- **What this is:** `UrlNormalizer.normalizeWebUrl` reconstructs a URI using decoded `path`, `query`, and `fragment`.
- **Problem:** For `https://example.com/a%2Fb?q=a%26b`, reconstruction turns encoded delimiters into `/a/b?q=a&b`. Signed links and URLs that distinguish encoded delimiters can break or identify a different resource.
- **Fix:** Preserve raw components while changing only the intended scheme/host/port. Define behavior for explicit nondefault ports and credential-bearing authorities. Do not decode and rebuild reserved delimiters.
- **If skipped:** Saved links and duplicate identity can be wrong. Add encoded slash, ampersand, equals, percent, Unicode, fragment, and signed-query cases.

### 7. Filtered search drops matching results before applying filters — medium, static

- **What this is:** `SearchViewModel.performSearch` obtains a globally limited pipeline result (default 40), then intersects it with `allowedIds`.
- **Problem:** If the first 40 query hits are outside the selected category, a matching result at position 41 is never considered. UI reports an empty filtered result incorrectly.
- **Fix:** Apply constraints before the result limit, or page until enough eligible results are collected. Keep fallback search behavior consistent.
- **If skipped:** Category/tag/health filters produce false negatives on ordinary larger libraries.

### 8. Reordering filtered subsets corrupts global ordering — medium, static

- **What this is:** `DashboardViewModel.onMoveCategoryToIndex` and `onMoveWebsiteToIndex` derive IDs from the displayed, query-filtered dashboard. Repositories assign indices starting at zero.
- **Problem:** Hidden rows retain their previous indices while visible rows receive overlapping positions. Clearing search changes the apparent ordering unexpectedly.
- **Fix:** Disable reorder while filtering, or apply the visible move to the complete canonical order. Preserve category boundaries and define concurrent update handling.
- **If skipped:** A local move changes unrelated positions and creates ambiguous sort order.

### 9. Dashboard duplicate counts are never populated — medium, static

- **What this is:** `EntityMappers.asDashboardCategory` calls `asWebsiteListItem`, which leaves `duplicateCount` at its default zero.
- **Problem:** `ObserveDashboardUseCase` uses `duplicateCount > 0`, but this dashboard data path never calculates it. Repository detail hydration does calculate it, so screens disagree.
- **Fix:** Compute duplicate membership/counts in a batched query or mapping pass using the same identity rules. Avoid adding one query per row.
- **If skipped:** Duplicate indicators and any dashboard duplicate section remain empty even with duplicate records.

### 10. Archive has no user-accessible recovery path — medium, static

- **What this is:** Dashboard archive always passes `archived = true`; category observers/selectors exclude archived categories. Feature-wide search found no unarchive control.
- **Problem:** Archiving hides a category and its links, but the app offers no way to retrieve it. This is not deletion, yet it behaves as disappearance to users.
- **Fix:** Add a minimal archived-category list with restore, plus clear feedback/undo on archive. Do not seed a new default category merely because all existing categories are archived.
- **If skipped:** Users need an external backup edit or database intervention to recover archived content.

## Should fix

### 11. Form and search state do not survive process death — medium, static

- **What this is:** AddEdit/Search ViewModels read initial navigation arguments from SavedStateHandle but keep ongoing form/query/filter changes only in MutableStateFlow.
- **Problem:** Android process recreation loses unsaved notes/tags/URL edits and search selections. Ordinary rotation retaining the ViewModel does not prove this safe.
- **Fix:** Save the minimal editable draft and search criteria in SavedStateHandle; reload derived metadata separately. Do not serialize the whole library or large backup payloads into saved state.
- **If skipped:** Backgrounding the app can lose ongoing work. Test real state restoration, not only recomposition.

### 12. Search hydration performs three extra database reads per website — medium, static performance risk

- **What this is:** `OfflineFirstWebsiteRepository.getAllWebsiteItems` hydrates each website by fetching its icon, tags, and duplicate candidates separately.
- **Problem:** Blank-query filtered searches and smart collections load the whole library; N entries cause roughly 1 + 3N reads before filtering. Duplicate matching increases work further.
- **Fix:** Batch icon/tag reads and duplicate counts, or query constrained records in Room. Reuse the existing batched dashboard pattern where appropriate.
- **If skipped:** Filter interactions slow as the library grows. Measure query count and elapsed time at 100/1,000/5,000 links before selecting a broader redesign.

### 13. Categories and result groups eagerly compose every child — medium, static performance risk

- **What this is:** Dashboard lazy items contain whole category Columns/FlowRows; `DashboardScreen.kt:546,569` iterates every website. Search groups similarly iterate results at `SearchScreen.kt:657`.
- **Problem:** A single large expanded category composes off-screen children. Stable `key` calls preserve identity but do not make children lazy. Category `animateContentSize` and `AnimatedVisibility` can amplify layout work during expansion.
- **Fix:** Flatten large lists into keyed lazy rows/grid items while preserving headers, ordering, focus, and accessibility. Profile before removing or changing animation. Keep small bounded chip rows simple.
- **If skipped:** Large categories can cause slow frames and memory growth. No measured jank claim is made here.

### 14. Image selection ignores emoji intent and has no load-error fallback — medium, static

- **What this is:** `Models.kt` returns cached/remote URLs even for EMOJI; `WebsiteIcon` checks URL before emoji. OG_IMAGE ignores the local cache. AsyncImage has no explicit fallback in this component.
- **Problem:** An emoji choice can display an old favicon instead; an invalid restored cache URI can leave a blank image; OG images require network again despite caching.
- **Fix:** Resolve display source according to the selected source, prefer valid local cache for remote sources, and show a deterministic local fallback on load failure.
- **If skipped:** Icon behavior differs from user choices and fails offline. Test every IconSource with missing/invalid cache files.

### 15. Restore validates only some relationships and copies device-local paths — medium, static

- **What this is:** `OfflineFirstBackupRepository.validateForeignKeys` checks categories, tags, and mappings, but not icon-cache references, duplicate identities, ranges, or local URI provenance. Restore writes saved cache paths unchanged.
- **Problem:** A backup from another installation cannot provide the referenced local files or SAF grants. Duplicate tag names with distinct IDs can be silently ignored by TagDao's IGNORE insertion when no cross-reference forces failure. Negative/zero IDs and inconsistent counts are not rejected up front. Saved-filter `specJson` is restored unchecked; `OfflineFirstSavedFilterRepository.decodeSpec` later parses JSON and enum `valueOf` without recovery, so malformed/unknown filter values can fail the search observer after an apparently successful restore.
- **Fix:** Validate identity uniqueness, positive IDs, field ranges, references and URL/URI policy before clearing. Treat caches as regenerable and custom assets as either explicitly portable assets or reported omissions. Surface `ImportSummary.warnings` in Settings; it currently discards them.
- **If skipped:** Successful restores can contain missing icons, discarded rows, misleading counts, or hidden warnings. Add database round-trip and failure rollback tests before changing the format.

### 16. Health monitor labels unsupported HEAD responses as dead — medium, static

- **What this is:** `UrlHealthMonitor.probe` uses only HEAD and maps most 4xx/5xx to DEAD.
- **Problem:** A usable site returning 405/501 for HEAD but 200 for GET is called broken.
- **Fix:** Use a bounded GET fallback only for unsupported HEAD cases, with the same URL policy, redirect rules, timeout, cancellation and byte limits. Do not classify every temporary server failure as permanent disappearance.
- **If skipped:** Healthy links receive false alarms. Add transport-driven status tests.

### 17. Activity-driven widget refresh has no broadcast result — high, static

- **What this is:** `MainActivity.onResume` calls `HomeWidgetRefresher`, which constructs providers and directly invokes `onUpdate` when widget IDs exist. All four providers call `goAsync()` and unconditionally call `pendingResult.finish()`.
- **Problem:** These manually constructed receivers are not processing a system broadcast and have no pending result. The finally block can throw a NullPointerException after refresh when a widget is installed. `onEnabled` also manually calls `onUpdate`; inspect combined enable/update broadcasts for repeated ownership transfer.
- **Fix:** Separate the reusable widget update operation from the broadcast lifecycle. Activity refresh calls the operation; real receiver delivery alone owns goAsync/finish, exactly once. Add bounded failure handling and tests for all four providers with widgets installed.
- **If skipped:** Returning to the app with a home widget can crash the process. This path was not exercised on the fresh emulator. Android documents goAsync as an operation within onReceive: [BroadcastReceiver reference](https://developer.android.com/reference/android/content/BroadcastReceiver).

### 18. Accessibility and state feedback need focused corrections — medium, static UI review

- **What this is:** Add/edit category color controls use bare clickable 36dp boxes (`AddEditScreen.kt:724–733`); icon controls include 32dp choices. Search filter deletion uses a small clickable trailing icon.
- **Problem:** Color options lack meaningful labels/selected-state semantics. Small visible controls and implicit hit expansion can overlap; actual accessible target sizes require device verification. Dashboard has no dedicated no-results/all-archived guidance.
- **Fix:** Use labelled selectable controls with explicit selected state and 48dp interaction containers, preserve compact visual swatches, and provide useful empty-state actions. Extract user-facing strings into resources as touched screens are corrected.
- **Observed on API 36:** Fresh dashboard, Settings and Add Website screenshots show black status-bar icons/time on the app's dark background. MainActivity uses default enableEdgeToEdge while the Compose theme is always dark. Set system-bar icon appearance consistently with the rendered theme; verify both system light/dark modes without changing the user's global setting as an incidental audit action.
- **If skipped:** TalkBack and large-font users cannot reliably identify or activate choices. Test font scale, RTL, keyboard/insets, dark/light themes and reduced animation; do not claim visual defects without screenshots.

### 19. Migration 2→3 loses tag associations under SQLite foreign-key enforcement — high; host reproduction, Android confirmation pending

- **What this is:** No Room migration, repository restore, feature ViewModel, pipeline decision, or functional UI test files were found. Current instrumentation only asserts the package name.
- **Problem:** A host SQLite 3.50.4 check built the exported v2 schema, inserted a category/website/tag/association, enabled foreign keys, and executed all 19 SQL statements extracted from MIGRATION_2_3 in a transaction. Website count remained 1, but tag-association count fell from 1 to 0. Dropping the old parent table cascades the association deletion. This establishes SQL behavior; Android Room execution still needs confirmation.
- **Fix:** Treat this as a must-fix data-preservation issue. Add an Android MigrationTestHelper reproduction, preserve/recreate dependent rows safely during table replacement, then verify all supported origins through v6. Add narrowly scoped tests for findings 1–18, restart persistence, and representative end-to-end flows.
- **If skipped:** Existing users upgrading from v1/v2 risk losing website-tag associations. Current green unit tests do not exercise migrations. Never use destructive migration fallback to make tests pass.

### 20. Documentation and redundant paths obscure current behavior — medium maintainability

- **What this is:** README still advertises encrypted `.lnen` backups; current serializer writes checksummed gzip/base64 JSON without encryption. Historical audits mix fixed issues and open claims. README says JDK 17, while daemon criteria select JetBrains JDK 21 (bytecode target remains 17).
- **Problem:** Users can mistake encoding/compression for confidentiality; future maintainers can re-fix resolved issues. Repository search found declaration-only candidates: AddWebsiteUseCase, WebsiteDao.insertWebsites, SmartSectionSheet, navigateToDashboard, and SettingsViewModel's onTileSizeSelected/resetExportStatus/resetImportStatus. normalizeStrict has test references and must not be blindly removed.
- **Fix:** Update current documentation, explicitly mark historical reports, and delete declaration-only paths only after checking DI/generated/dynamic references and rebuilding. Preserve repository interfaces and module boundaries unless a concrete benefit is demonstrated.
- **If skipped:** Wrong expectations and duplicate implementations increase maintenance cost. No dependency removal or exact line savings is justified yet.

## Additional investigation, not verified defects

- AppSearch session creation/warm/rebuild are guarded by volatile fields, not mutual exclusion. Startup and search can call them concurrently. Reproduce reset/rebuild races before selecting synchronization; avoid deadlocks from warm/reindex recursion.
- Search requests use `onEach` rather than cancellation of stale work. A slow old query can publish under newer query text. Add controlled delayed-result tests, then use latest-request semantics if reproduced.
- Public-target checks perform DNS validation separately from connection resolution. The code documents DNS-rebinding exposure; enforce checked addresses at connection time if remote fetching remains enabled.
- Metadata refresh replaces good metadata with generated fallback values on failure. Confirm worker scheduling and active callers before changing behavior.
- Backup staging overwrites `latest-backup.json` directly. Test interrupted writes and overlapping exports; use atomic replacement if staged recovery is part of the product promise.
- Static resource leak: IconStorageManager.cacheIcon leaves a partial temp file when an oversized stream or I/O failure throws before successful cleanup. Own it through finally and test failures; repeated failures otherwise accumulate files in app files storage.
- Cancelling the backup-folder picker currently calls `onBackupFolderSelected(null)` and clears the existing folder. Verify on device, then preserve selection on cancellation and report failed persistable-grant acquisition.
- “Last Imported” is computed from IDs/creation time rather than import provenance. Rename to reflect existing behavior unless genuine import tracking is required.
- Theme is intentionally implemented as one dark color scheme; light-theme support is a product enhancement, not an established regression. The current health scheduler uses CONNECTED plus battery-not-low, contradicting the older audit's unmetered/charging claim. Reconcile docs and choose constraints from the desired maintenance frequency rather than blindly restoring old code.
- Release ProGuard rules keep whole OkHttp, Jsoup, Coil, AppSearch and other namespaces and suppress broad warning classes. Measure release size and review consumer rules before narrowing these; no release-size saving is claimed without an R8 build and smoke tests.

## Cleanup and maintenance plan

Keep the existing 13-module structure. Do not create a new architecture or move packages solely for symmetry. Retain Gradle wrapper files, Room schema history, manifests, baseline profile, resources and useful tests. Build outputs and local caches are already ignored; their disk presence is not source-tree debt.

Use `git ls-files` as the source-tree authority. Recheck every deletion candidate across source, tests, manifests, Gradle, reflection strings, and generated DI. Remove only proven unused code, then remove imports/dependencies made unused by that deletion. Do not delete single-implementation repository interfaces merely because they have one implementation.

Keep AGENTS.md authoritative; reconcile AGENT.md and CLAUDE.md instead of leaving conflicting rules. Keep historical audit files as dated evidence with links to this current report. Move root design references into a documented assets location only if their references are updated and the move improves navigation. No cache wipe or wholesale tree cleanup is required.

Extract unrelated UI sections only when a fix needs independent testing or a reused component. Centralize the actual repeated rules: URL/network trust, image source selection, duplicate identity, and restore validation. Avoid adding generic wrappers around existing action/use-case layers.

## Evidence and limitations

Fresh host/device validation results are recorded in `deep-scan-validation-2026-11-14.md`. Historical build/lint reports are not current evidence. No data-replacing restore, storage clearing, production signing, or dependency upgrade was performed.

For the lazy-layout recommendation, Android documents that ordinary Columns compose all children and that lazy layouts compose visible items: [Lazy lists and grids](https://developer.android.com/develop/ui/compose/lists). Migration acceptance should include all supported origins and populated-data preservation: [Room migration testing](https://developer.android.com/training/data-storage/room/migrating-db-versions). Use APIs compatible with this repository's Room 2.8.0; do not copy newer Room 3 dependency coordinates into this project.

Verdict: Fix data-loss semantics and trust-boundary gaps first; then search correctness, recovery UX, and measured performance. A broad cosmetic rewrite is not justified.
